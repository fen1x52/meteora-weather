# Meteora 1.0

Адаптивное веб-приложение для погоды, качества воздуха, астрономии и природных событий. Русский язык по умолчанию, английская локализация, светлая и тёмная темы, полупрозрачные панели Liquid Glass и интерфейс в духе Material 3 Expressive.

Приложение использует реальные внешние API. Если источник не отвечает или не покрывает регион, интерфейс показывает ошибку либо ограничение покрытия. Случайно сгенерированные погодные показатели и вымышленные предупреждения не используются.

## Быстрый запуск

Нужны Node.js 22 или новее, npm и доступ в интернет. Зависимости закреплены в `package-lock.json`.

```sh
npm ci
npm run dev
```

Откройте `http://127.0.0.1:3000`. Если порт занят, Next.js покажет другой адрес. На первом открытии загружается выбранный по умолчанию город; изменить его можно поиском, геолокацией с разрешения пользователя или выбором точки на карте.

Production-сборка и её локальная проверка:

```sh
npm run build
npm start
```

`npm start` обслуживает готовую папку `out/` через небольшой статический сервер, привязанный к `127.0.0.1`. Переменная `PORT` позволяет выбрать порт. Это локальный сервер проверки, для публичного размещения используйте HTTPS-хостинг.

## Разделы

| Маршрут | Назначение |
| --- | --- |
| `/` | Текущая модельная погода, ближайшие часы, основные показатели и обзор по правилам |
| `/forecast` | Почасовой и дневной прогноз до 14 дней, сравнение дней, исторический реанализ |
| `/maps` | Интерактивная карта, прошедшие кадры радара осадков, реальные показатели выбранной точки |
| `/air-quality` | Европейский и американский AQI, концентрации загрязнителей и модельный прогноз |
| `/astronomy` | Фаза Луны, восходы и закаты, золотой час, длина дня и ночи, планетарный Kp |
| `/nature` | Землетрясения USGS и открытые природные события NASA EONET, включая пожары |

| `/favorites` | Управление избранными городами |
| `/alerts` | Погодные рекомендации по правилам и официальные предупреждения там, где доступен источник |
| `/settings` | Язык, единицы измерения, тема, анимации, уведомления и локальные данные |

## Технологии и архитектура

Next.js 16 App Router, React 19, строгий TypeScript, Tailwind CSS 4, Motion, Lucide, Leaflet и SunCalc. Сборка — стандартный `output: 'export'` Next.js: настоящие интерактивные React-страницы и статические файлы, которым не нужен Node-сервер во время работы. Данные запрашиваются в браузере после загрузки страницы.

```text
src/app/                 маршруты, layout и глобальный стиль
src/components/          оболочка, состояние приложения, общие компоненты
src/components/pages/    функциональные страницы
src/lib/types.ts         модели и контракты данных
src/lib/api.ts           источники, запросы, проверки, кэш
src/lib/weather.ts       единицы, форматирование, погодные правила
src/lib/astronomy.ts     астрономические расчёты
src/lib/use-resource.ts  жизненный цикл загрузки
src/lib/*.test.ts        тесты критической логики
scripts/serve.mjs        локальный сервер production-сборки
scripts/smoke-api.mjs    проверка доступности настоящих API
```

Основные измерения хранятся в системе источника: температура °C, ветер м/с, давление гПа. Пользовательские единицы применяются при отображении. Временные отметки API передаются как Unix timestamps; даты и часы форматируются для часового пояса выбранного места. Отсутствующее числовое значение остаётся отсутствующим и не заменяется нулём.

Запросы имеют таймаут, ограниченный повтор и кэш в памяти с отдельным TTL источников. Одновременные одинаковые запросы объединяются. Кэш не является офлайн-базой; после перезагрузки вкладки данные запрашиваются заново. Время получения ответа отделено от времени прогнозного значения или события.

## Что означают данные

| Источник | Тип данных и ограничения |
| --- | --- |
| [Open-Meteo Forecast](https://open-meteo.com/en/docs) | Текущие условия и прогноз из численных погодных моделей. Это не показания ближайшей станции. Горизонт и полнота зависят от модели и региона. |
| [Open-Meteo Historical](https://open-meteo.com/en/docs/historical-weather-api) | Исторический реанализ. В приложении выбран консервативный предел: до 93 дней за запрос, окончание не позднее пяти дней назад; архив — с 1940 года. |
| [Open-Meteo Air / CAMS](https://open-meteo.com/en/docs/air-quality-api) | Модельные концентрации и индексы качества воздуха, а не локальный датчик. Европейский и американский индексы имеют разные шкалы. |
| [RainViewer](https://www.rainviewer.com/api/weather-maps-api.html) | Радарные изображения прошедших часов. Покрытие не всемирное; отсутствие окраски не доказывает отсутствие осадков. Кадр может объединять измерения разного времени. |
| [USGS](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php) | Землетрясения магнитудой 2,5 и выше за последние сутки. Каталог и оценки событий могут уточняться. |
| [NASA EONET](https://eonet.gsfc.nasa.gov/docs/v3) | Открытые события за последние 30 дней. Это курируемый каталог, не полная система обнаружения пожаров или экстренного оповещения. |
| [NOAA SWPC](https://www.spaceweather.gov/products/planetary-k-index) | Оценка планетарного трёхчасового Kp, не локальный прогноз сияния. |
| [NOAA NWS](https://www.weather.gov/documentation/services-web-alerts) | Официальные предупреждения для поддерживаемой территории США. Для других стран отображается отсутствие подключённого источника. |
| [SunCalc](https://github.com/mourner/suncalc) | Геометрические расчёты Солнца и Луны для координат и даты. Видимый горизонт, рельеф и облака могут изменять условия наблюдения. |

Температура, ветер и облачность на карте представлены показателями выбранной точки Open-Meteo. Сплошных растровых слоёв этих величин без подключённого поставщика тайлов нет. Радар осадков — отдельный действующий слой RainViewer; он не заменяется искусственной тепловой картой.

Текстовые обзоры и рекомендации формируются детерминированными правилами на загруженных данных. Это не ответы отдельной ИИ-модели и не официальные предупреждения. Официальные сообщения показаны отдельно с источником.

## Лицензии и эксплуатация

Открытые API не требуют ключей для предусмотренного бесплатного использования. Это не означает разрешение на любое коммерческое использование или гарантию доступности.

- [Open-Meteo Free API](https://open-meteo.com/en/terms) предназначен для некоммерческих проектов: менее 10 000 запросов в день, 5 000 в час и 600 в минуту; данные требуют атрибуции CC BY 4.0. Перед коммерческим запуском нужен соответствующий [платный план](https://open-meteo.com/en/pricing).
- Для воздуха указывается Open-Meteo и Copernicus Atmosphere Monitoring Service / CAMS ENSEMBLE.
- [RainViewer API](https://www.rainviewer.com/api.html) рассчитан на личное, образовательное и небольшое общественное использование без SLA. Для коммерческой нагрузки согласуйте условия с поставщиком. Атрибуция обязательна.
- Базовая карта содержит атрибуцию © OpenStreetMap contributors. Стандартные тайлы подчиняются [правилам OSMF](https://operations.osmfoundation.org/policies/tiles/): нельзя массово скачивать их, загружать офлайн-области или скрывать атрибуцию. Для большого трафика нужен подходящий провайдер тайлов или собственная инфраструктура.
- Соблюдайте ссылки и атрибуции первичных поставщиков NASA EONET; каталог не передаёт автоматически права на сторонние материалы.

Статический клиент не содержит секретов. Не помещайте API-ключи в `NEXT_PUBLIC_*`, исходники, `localStorage` или параметры клиентских запросов. Для платного источника добавьте серверный шлюз с ключом из секретного окружения, проверкой координат и дат, общим кэшем, ограничением частоты и фиксированным списком адресов источников. Публичный произвольный URL-прокси создавать нельзя. Переход на серверный режим Next.js потребует убрать `output: 'export'` и выбрать серверный хостинг.

## Настройки, приватность и уведомления

Настройки, выбранное место, недавние поиски и избранное сохраняются локально в браузере. Аккаунта, серверной базы профилей, рекламной аналитики и межустройственной синхронизации в этой версии нет. Очистка данных доступна в настройках; очистка хранилища браузера также удалит предпочтения.

Координаты выбранного места передаются погодным API для получения данных; поисковый текст — Open-Meteo Geocoding. При геолокации браузер сначала запрашивает разрешение. Сторонние сервисы получают обычные сетевые метаданные запроса согласно собственным политикам.

Браузерные уведомления зависят от поддержки Notifications API, HTTPS (либо localhost) и явного разрешения пользователя. Они работают в рамках открытого приложения. Серверных Web Push-подписок, фоновой отправки при закрытом сайте и гарантированной доставки нет. Для такого режима потребуются service worker, Push API, сервер подписок, VAPID-ключи, планировщик и механизм отписки; интерфейс не выдаёт локальные уведомления за push-сервис.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
# Полный цикл:
npm run check
# Отдельная проверка внешних сервисов, требует сети:
node scripts/smoke-api.mjs
```

Unit-тесты проверяют логику, не требуют доступности погодного сервера и не используются как данные интерфейса. Smoke-скрипт отправляет один реальный запрос каждому источнику, проверяет форму ответа и сообщает HTTP/CORS; он не сохраняет примеры прогнозов. Сбой такого теста может означать сетевой отказ, лимит или изменение внешнего API. HTTP-успех в Node не заменяет проверку CORS и поведения в браузере.

Фактические результаты проверки конкретной поставки и оставшиеся ограничения находятся в [`docs/QA.md`](docs/QA.md).

## Развёртывание

1. Выполните `npm ci`, затем проверки и `npm run build`.
2. Разместите содержимое `out/` на HTTPS-хостинге статических файлов. Не публикуйте `node_modules/` и служебные файлы.
3. Включите выдачу `index.html` для каталогов и `404.html` для неизвестных адресов. Встроенные маршруты используют завершающий `/`; переписывать все запросы на главную страницу не требуется.
4. Сохраните `_next/` и все вложенные файлы. Для хешированных `_next/static/` допустим долгий immutable-кэш; HTML должен обновляться при новом релизе.
5. Разрешите клиентские HTTPS-запросы к документированным поставщикам. При собственной Content Security Policy учтите inline-скрипты гидрации Next.js, Leaflet, URL тайлов и изображения данных; сначала проверяйте политику в Report-Only.
6. Проверьте прямое открытие всех десяти маршрутов, поиск, запрос реальных данных, переключение единиц, карту и восстановление настроек.

`.openai/hosting.json` описывает публикацию в Sites. Его `project_id` относится к созданному сайту; при независимом размещении в другом аккаунте не переиспользуйте чужую идентичность проекта. Встроенный Sites доступ и адрес задаёт хостинг, а не клиентский код Meteora.
